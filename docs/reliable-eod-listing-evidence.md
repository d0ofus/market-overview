# Verified first-trading sessions

Listing age is an explicit, versioned fact. The first retained bar, Yahoo `firstTradeDate`, ETF inception, an issuer's unit IPO and a ticker rename do not automatically establish a common share's first trading session. Unknown histories remain missing coverage.

The initial reviewed claims are BRTM Class A ordinary shares commencing separate trading on September 10, 2026 ([issuer SEC announcement](https://www.sec.gov/Archives/edgar/data/2131350/000119312526385209/d102609dex991.htm)), and GOLS beginning exchange trading on January 2, 2026 ([issuer confirmation](https://gabelli.com/research/gabelli-introduces-gols-a-new-way-to-access-the-global-sports-economy/)). BRTMU's July 21 unit IPO and RSHO/WELD's June 22 rename cannot pass these claim rules. Additional securities require a reviewed source/claim mapping; the importer does not infer dates from generic announcement text.

`worker/scripts/register-eod-listing-evidence.ts` downloads the exact official document, verifies a verbatim normalized quotation containing the security identity/trading date and the separate publication-date phrase, checks actual stored security identity, and reads retained SIP and Yahoo history to reject earlier observations. Redirects, non-text documents, oversized documents and source failures stop the import. GOLS's stored `ARCA` venue normalizes to `NYSE Arca`. If BRTM has no Core row, the only identity fallback is the exact SEC common-share/venue statement corroborated by an actual, dated Nasdaq membership with `source_ticker=BRTM`; it neither fetches another Nasdaq file nor creates a Core row. An existing contradictory Core row always fails.

The operator supplies a JSON object matching `listingEvidenceImportSchema`: version, initial-listing event, exact security identity, listing date, publication date, effective session, source URL, verbatim quotation, both date phrases and the superseded evidence hash (initially null). A source quotation may contain up to 3,000 characters because the GOLS article's date appears after the article body. Do not edit or manufacture source text to make a claim pass.

Required environment settings are `EOD_LISTING_IMPORT_APPROVED=true`, `EOD_LISTING_IMPORT_PATH`, `EOD_LISTING_IMPORT_MODE`, `EOD_LISTING_USER_AGENT` (an actual contact identity containing an email), `EOD_CODE_REVISION`, `EOD_STORAGE_MIGRATION_ID`, `CLOUDFLARE_ACCOUNT_ID`, `EOD_CORE_DATABASE_ID`, `EOD_MARKET_DATABASE_ID`, `EOD_HISTORY_DATABASE_ID`, `EOD_OPS_DATABASE_ID`, `CLOUDFLARE_EOD_D1_TOKEN` and the applicable `EOD_BUDGET_PROFILE`. `CLOUDFLARE_EOD_ANALYTICS_TOKEN` is used when separately configured. GitHub CLI must already be authenticated. The market database is the migration's actual target. These settings are validated; credentials and document bodies are never printed.

Run from clean, pushed main:

```powershell
node --import tsx worker/scripts/register-eod-listing-evidence.ts
```

Before cutover, the checkout and `EOD_CODE_REVISION` must match the approved migration executor exactly. After production configuration is recorded, a newer clean GitHub main may run the same operator only when it descends from the approved production revision and changes exclusively allowed web/documentation files, with all Worker, scripts, workflow and dependency files unchanged. `EOD_CODE_REVISION` remains the actual approved production code; the evidence records the actual operator checkout revision.

Use `future-session` during private reconstruction, after the prior daily owner has completed and before freezing the next session. `effectiveFromSession` must be at least the actual New York registration date and must be a stored exchange session. Thus a September 11 verification may describe a September 10 first trade while remaining absent from September 10 inputs. The importer refuses to alter an affected running or frozen incomplete run. It does not change price revision clocks, prior inputs, checkpoints or accepted publications. The normal next-session coordinator or measured population-expansion operation freezes the new references.

Use `reconstruct` only after the storage migration and production configuration are completed. Registration and queuing an active reconciliation run with fresh inputs are one atomic Ops transaction. Existing completed daily publications remain available until the reconciliation publishes a new revision. A completed reconciliation is reset to fresh inputs; an already executing frozen run blocks import. The Cloudflare coordinator dispatches the queued run through the existing workflow. An accepted registration or queued run is not proof of completed publication; inspect the actual run and publication revision.

Records use existing `eod_rollout_evidence`; no market/history schema changes are required. The mutable registry retains immutable version references, selects the latest applicable version separately for each session and rejects decreasing effective sessions. Identical claims are idempotent even if unrelated HTML changes: the original document hash, verification time and evidence hash are retained. Replaying an older superseded claim cannot revert the current version.

Frozen inputs contain only compact ticker/date/hash references, and omit `listingEvidence` entirely when none applies. Evidence older than every relevant 252-session/YTD anchor stays in the registry but is omitted from new run inputs. Unknown members are never removed to fit a limit. Registry history is bounded at 400 versions and 1.8 MB; frozen inputs with listing evidence are limited to 1.8 MB before the D1 write. Exceeding either limit fails explicitly and requires a separately reviewed capacity change.

When evidence exists, null fields distinguish `verified-recent-listing` from `missing-required-session`. First-day shares remain in total membership but are structurally ineligible for adjacent-session returns. Each moving average, rolling high and return has its own required-session population. Unknown gaps still count against the unchanged 98% S&P / 95% other-universe gates. Storage acceptance reloads immutable evidence and recomputes all structural denominators independently. Validated structural gaps do not consume Yahoo requests or expand primary lookback before listing; existing five-session reconciliation and recovery of eligible missing prices remain intact. Older no-evidence inputs, feature payloads, page payloads and hashes retain their exact prior behavior.

A price observation before a verified first trading session quarantines that security's calculated fields with an explicit listing-history contradiction. The runner preserves the stored observations and evidence for repair, skips fallback for the suspect identity, and continues independent symbols and publication scopes. It does not silently discard the contradictory bar and calculate from the remaining history.
