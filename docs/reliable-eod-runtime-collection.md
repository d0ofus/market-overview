# Measured Worker runtime evidence

The existing telemetry collector remains available with `EOD_RUNTIME_COLLECTION_MODE=telemetry`. It re-fetches the authenticated historical invocation window during acceptance. A 401/403 is terminal for that attempt; the runner does not repeatedly query a denied endpoint.

The optional `EOD_RUNTIME_COLLECTION_MODE=live-tail` uses Cloudflare's authenticated Start Tail API and `trace-v1` WebSocket, opened before any private probe. Start Tail accepts either Workers Scripts Write or Workers Tail Read. It is a separate supported capability from historical Observability queries. [Cloudflare Start Tail API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/tail/methods/create/)

For the unattended local controller, persist `"runtimeCollectionMode": "live-tail"` in its ignored reviewed configuration. The optional `"runtimeAttempt": 1` selects the existing bounded candidate discriminator (1–4); the default remains 1. Each attempt has its own `runtime-evidence-attempt-N.json` in the existing code/session/publication artifact directory. Advancing an attempt preserves the earlier receipt and file while reusing only matching publication-growth/capacity inputs. The same selected file is passed to acceptance. These are local collector options, not Worker bindings. The candidate still has a distinct name, no routes/cron/queues, its own derived admin credential, read-enabled target/history bindings, actual code SHA, full invocation logging and sampling rate 1.

The collector verifies the exclusive serving version, opens the authenticated stream, completes protocol setup and a server ping/pong, then claims an immutable Ops attempt with exactly five independent request nonces. It sends two Overview requests, two Breadth requests and one coordinator request. Each response must be HTTP 200 with its actual `cf-ray`. Each full platform invocation must identify that exact request nonce/ray, candidate name/version, successful outcome, finite platform CPU time and exactly one complete final D1 counter summary. CPU is the platform `TraceItem.cpuTime` in milliseconds, not elapsed response time or a GraphQL average. The final counter summary includes telemetry writes and admission settlement. [Cloudflare TraceItem runtime implementation](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/trace.c%2B%2B), [official Wrangler tail transport](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/tail/createTail.ts)

Unknown control frames, overload/sampling notices, truncation, missing CPU/version/correlation, exceptions, duplicates, extra requests, incomplete D1 metadata, disconnects and timeouts all fail closed. The collector also requires exactly five durable counter claims and matching stored sample identities; it cannot select five successful samples from a larger attempted set. The tail is closed and deleted in `finally`. A dropped connection cannot be repaired by silently repeating the requests. Real-time logs are not stored, and Cloudflare may drop events at high traffic. [Cloudflare real-time log limits](https://developers.cloudflare.com/workers/observability/logs/real-time-logs/)

Only sanitized CPU/query counters, request/sample IDs, script/version/database identities, publication/plan hashes and truthful collection timestamps enter `eod-runtime-tail-receipt:<probeId>:<workerVersion>` in Ops. No headers, secrets, cookies, request/response bodies, raw logs, WebSocket URL or capability token are persisted or printed. This is an attestation by the reviewed, pinned collector with authenticated platform access, not a Cloudflare cryptographic signature. There is no raw JSON import command. The local artifact is only a receipt reference: acceptance independently loads the immutable Ops record, validates the attempt and durable sample counters, and rechecks actual exclusive deployment, current accepted publications and input clocks. Existing CPU/query ceilings and runtime freshness limits remain unchanged. Receipt replay never changes its original measurement/collection dates.

If collection was interrupted after its durable claim, preserve all attempt/sample records and the existing candidate. Inspect the fixed failure reason. For a confirmed transport-only interruption, an operator may increase `runtimeAttempt` to the next unused value (maximum 4), yielding a new private candidate and receipt identity; the prior attempt is not overwritten. Do not advance attempts to discard a genuine CPU/query limit failure. Correct the implementation and approve the resulting code revision instead. A completed receipt can be recovered without re-probing by running `prepare-eod-runtime-candidate.ts collect` with its same selector and identity. An expired receipt requires new truthful measurements, never a changed timestamp.

The existing token passed a bounded live wire check using one temporary diagnostic Worker with the candidate's compatibility date, version metadata and explicit full invocation logging. A single read-only health request produced numeric platform CPU time, the exact deployed script/version, successful outcome, nontruncated trace, numeric event timestamp, HTTP 200 status, `cf-ray` and the custom request-ID header. The benign health marker also arrived. The Worker had no database bindings, secrets, production routes or schedules. Its tail was deleted successfully; Worker deletion was verified by a subsequent 404. This establishes wire compatibility, not EOD performance: no diagnostic result was stored as acceptance evidence. The real five-probe candidate must still satisfy every CPU/query, publication and coverage gate.
