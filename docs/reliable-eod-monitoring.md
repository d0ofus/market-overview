# EOD operation evidence and historical recovery

`EOD operating evidence` runs daily at 00:35 UTC, including holidays and weekends, and can be dispatched manually. It shares the `market-eod-writer` concurrency group with ingestion and storage migration. A single admitted control query establishes actual metered EOD activity for that UTC bucket. It is independent of the Worker ingestion canary/disable gate, never requests market prices and requires only the existing Cloudflare D1/analytics credentials.

The `market-eod` environment variable `EOD_RUNNER_MODE` defaults to `shadow`. Set it to `active` only with the verified public Worker binding/read cutover. Changing that variable alone cannot produce retirement credit. The public cutover must also record `eod_rollout_evidence.id='monitoring:public-activation'` with this exact JSON shape:

```json
{"version":1,"activatedAt":"<actual activation ISO timestamp>","codeRevision":"<40-character deployed Git revision>","marketDatabaseId":"<actual public market D1 UUID>"}
```

Do not backdate activation to private target bootstrap or shadow ingestion. The first complete public delivery is the later of activation and the first accepted publication for every required scope. Sessions whose deadlines passed before activation receive no credit. Rollback must disable public EOD reads and return the monitoring workflow mode to `shadow`; preserve the activation record as historical evidence rather than inventing continued public delivery.

The user removed the elapsed observation period on 11 September 2026. Retirement no longer waits for three sessions, ten sessions, a weekend run or finalized historical usage buckets. The two-hour publication target and correctness, capacity, quota and runtime limits still apply.

`collectEodRolloutMonitoring` separately reports `currentHealth` and historical diagnostics. Current health requires all six accepted pointers for the expected exchange session, checksummed publications matching the completed active run, no pending input revision, a real public activation record, active public reads and current UTC quota evidence. Account analytics and metered ledgers must be present, at most five minutes old for an explicit retirement decision, and within the existing EOD (2.5 million reads/50,000 writes) and account (4.5 million reads/90,000 writes) limits including outstanding reservations. Missing records are unknown, never zero. The technical cutover validator still verifies payloads, coverage, retained history, storage and runtime evidence independently.

The last three finalizable exchange sessions remain operational history only. Their cutoff is the earlier of the expected session and UTC today minus two days; newer deadlines appear separately while usage settles. Historical checks still use actual exchange closes, early closes and daylight-saving changes, six scopes, and the earliest accepted revision per scope. A late first publication stays marked late after successful recovery. Recovering the current pointers can restore current health without waiting for a new session to erase the old failure. Historical gaps and failures remain visible in `sessions`, `newerSessions`, `usageDays` and `operationalReasons` and do not silently become passing observations.

Full-UTC-day usage is collected after a complete additional UTC day to allow analytics delay. It combines settled D1 response counters with conservative high-water marks from account analytics and shared workflow metering; provider analytics are reported estimates, not invented exact billing totals. All historical usage rows now have `requiredForRetirement:false`. Collection continues on weekends and holidays for operations, with at most three historical analytics requests per invocation: two recent correction rechecks and one older missing bucket within 30 days. Quota deferrals retain pending evidence and do not trigger repeated attempts.

The policy constant is `current-health-no-observation-v1` with zero required sessions. Monitor version 3 is stored at `monitoring:current-health-no-observation-v1`; old three- and ten-session caches cannot establish current health. Public/admin reads use one indexed cached record and never start collection. Historical monitoring expires after 30 hours; the separate current-health claim expires after five minutes and is then explicitly unverified. `assertEodRetirement` validates the technical cutover approval, recollects current health and requires that fresh result for the deployed revision. No hand-submitted multiday retirement proof is needed, and empty historical arrays cannot substitute for actual current publications or usage.

The Admin recovery card treats verified public cutover, a completed controller and matching recorded configuration as durable recovery completion. Current delivery and quota health appear separately with their observation dates. An aged quota sample or later operational failure does not undo a recorded migration, and recorded migration completion does not claim that current delivery is healthy. Neither monitoring eligibility nor the removal of the observation period deletes data, changes bindings, enables pruning or retires jobs automatically.

Historical repair retains validated older bars even when a target-session bar is unavailable, and reports that target gap explicitly. Coverage uses the union of retained and newly verified observations. A retry reopens a previously partial cursor and fetches only unresolved windows; restored rows clear old diagnostics. The runner rejects unordered, duplicate, future-extended or target-truncated exchange grids before provider work. It does not infer listing dates from short histories.

Historical breadth publication revalidates frozen membership provenance. Source types must match the universe, source and verification dates cannot lie after the target session, and a previous matching membership is usable for at most five actual exchange sessions. Bundled lists, unrelated source classes, malformed dates and unverifiable legacy inputs remain unavailable. Current membership is never substituted for an older session's missing evidence.
